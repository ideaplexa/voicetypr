# Dictation and voice-agent competitive research

**Research snapshot: 12 November 2026.** Prices are the USD list prices shown on the cited primary pages unless another currency is specified; annual monthly equivalents are billed annually. Features, licenses, and prices can change. `UNSOURCED` means not established from sources consulted—not that the answer is no. GitHub stars are point-in-time repository totals, not active users; repository `pushed_at` is repository activity, not proof that a particular shipped app was released on that date. Claimed privacy/compliance is the vendor's description, not an independent audit. Release samples below are observed releases, not a calculated complete cadence. Links in the matrix point to evidence in the profiles immediately above it.

## Mobile and store architecture facts

- **iOS keyboard boundary.** Apple says custom keyboards cannot use the microphone; secure fields, phone pads and host apps that disallow custom keyboards can force the system keyboard. The Apple extension guide is archived, so version-specific behavior still needs device validation. Full Access permits shared-container/network capability; it does not grant the keyboard microphone access. [Apple extension guide](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html).
- **Concrete shipping workaround.** OpenWhispr documents keyboard Full Access, switching into its containing app to start recording, switching back, background recording, and sharing via app storage; mobile private processing is on-device. This is an observed documented product flow, not a claim every competitor implements the same lifecycle. [OpenWhispr iOS](https://docs.openwhispr.com/platform/mobile). Monologue documents keyboard Full Access and cloud iOS processing, but not enough here to assert its exact app-switch lifecycle. [Monologue](https://docs.monologue.to/account-and-privacy/permissions-and-privacy). VoiceInk has separate Action Button/Back Tap Quick Dictation with manual paste; VivaDicta documents keyboard/main-app IPC and prewarm. [VoiceInk](https://tryvoiceink.com/docs/quick-dictation), [VivaDicta](https://github.com/n0an/VivaDicta).
- **Memory:** extensions are memory-constrained, with limit varying by device/OS; no Apple-guaranteed universal MB cap established. A developer forum reports approximately 30–48 MB, but that is a developer observation, not a platform contract. Putting model inference in the containing app avoids assuming the model will fit in the keyboard process. [developer discussion](https://developer.apple.com/forums/thread/826851), [KeyboardKit memory discussion](https://docs.keyboardkit.com/documentation/keyboardkit/developer-memory-management/).
- **Background audio and system affordances:** apps declare background execution modes and configure audio sessions; they are not a blanket entitlement to indefinitely record or restart recording in any state. Permission, user disclosure, actual review and OS lifecycle matter. [Apple background modes](https://developer.apple.com/documentation/xcode/configuring-background-execution-modes), [record session](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/record). OpenWhispr documents an active session continuing in background; VoiceInk documents an Action Button/Back Tap + Live Activity; Cursor has Siri and Live Activity controls. [OpenWhispr](https://docs.openwhispr.com/platform/mobile), [VoiceInk](https://tryvoiceink.com/docs/quick-dictation), [Cursor](https://cursor.com/changelog/voice-chat). FluidAudio supplies on-device Core ML models for iOS; VivaDicta documents WhisperKit and Parakeet on device. [FluidAudio](https://github.com/FluidInference/FluidAudio), [VivaDicta](https://github.com/n0an/VivaDicta).
- **Android:** an IME is a service and can provide voice input subject to microphone permissions and foreground/background restrictions, which differ from iOS's keyboard-extension prohibition. Android exposes `SpeechRecognizer.createOnDeviceSpeechRecognizer` when a device has a suitable on-device service; on-device model availability is not universal. [IME](https://developer.android.com/develop/ui/views/touch-and-input/creating-input-method), [SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer), [microphone foreground service requirements](https://developer.android.com/develop/background-work/services/fgs/service-types). [WhisperType](https://f-droid.org/packages/me.trion.whispertype/) explicitly describes an offline Android keyboard; its bundled model details are `UNSOURCED` in this pass.
- **App Store commercial terms, 2026, not legal advice:** Apple's 3.1.1 generally requires IAP to unlock in-app functionality and says own unlock mechanisms such as license keys are not permitted. 3.1.1(a) says US storefront apps need no external-link entitlement for buttons/links/calls to action; that is not itself blanket permission to bypass all IAP/unlock rules. Exceptions including multiplatform services require review against their precise terms, not assumption that external keys are always valid. Superwhisper documents a cross-platform key and iOS purchase; observed practice is not an Apple legal ruling. [App Review Guidelines §§3.1.1–3.1.3](https://developer.apple.com/app-store/review/guidelines/), [Superwhisper](https://superwhisper.com/docs/billing/plans).
- **EU:** Apple's unified terms effective Oct 1 2026 permit alternative in-app payment and out-of-app offers alongside or instead of IAP, subject to entitlement, disclosure, age protections, applicable commission/reporting, and maintaining payment options for 12 months; offering only alternatives has additional choice requirements. Out-of-app links are not automatically commission-free. Apple explicitly says previous EU addenda were superseded by Attachment 14. [EU overview](https://developer.apple.com/support/apps-in-the-eu), [EU payment details](https://developer.apple.com/support/payment-options-on-the-app-store-in-the-eu).

## Gaps nobody fills well — bounded evidence, not a market-wide proof

These are **user-reported friction points**, not verified universal deficiencies or representative surveys. Existing competitors may partially address them; “nobody” is not established by this sample.

1. **iOS keyboard return and input continuity.** An April 2026 Reddit commenter reports the companion-app round trip makes the Reddit comment box disappear and keyboard polish fail; the developer says a longer connection should reduce switching. [Firsthand thread](https://www.reddit.com/r/LocalLLaMA/comments/1r93i0p/local_ios_voice_to_text_app_alternative_to_wispr/). An April X user says the extra Wispr iOS swipe “killed the magic”; a reply recommends Action Button. [X thread](https://x.com/manosaie/status/2046608406006346110).
2. **Visible low-latency transcription vs final quality.** A January 2026 HN user complains Wispr is slow and transcribes after finishing, asking for streaming; the maintainer reply discusses context/accuracy tradeoffs. This is a dated individual observation, not a current benchmark or proof no competitor streams. [HN](https://news.ycombinator.com/item?id=46824506).
3. **Speak → edit → listen loop on mobile.** The same Reddit user requests a button to read the polished output aloud; their keyboard polish was not working in that scenario. This indicates a requested workflow, not absence of TTS everywhere. [Reddit](https://www.reddit.com/r/LocalLLaMA/comments/1r93i0p/local_ios_voice_to_text_app_alternative_to_wispr/).
4. **CLI microphone access without requiring a particular vendor account.** An OpenCode issue requests voice input as an MCP server for terminal agents; Claude Code's official implementation explicitly requires a Claude.ai login and local mic and excludes API-key/remote sessions. Existing MCP alternatives mean the unmet part is integration/reliability for the reporter, not absence of any implementation. [OpenCode issue](https://github.com/anomalyco/opencode/issues/41413), [Claude Code docs](https://code.claude.com/docs/en/voice-dictation), [mcp-listen](https://github.com/decibri/mcp-listen).
