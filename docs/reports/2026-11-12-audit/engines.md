# Speech engines and transport audit — beta.8

Static, read-only inspection of `transcription`, `whisper`, `parakeet`, `cloud_stt`, `remote`, `provider_capabilities`, `transcript-text`, and `vulkan-device-select`, with the production dispatch points in `commands/audio.rs`, `audio/stream_tap.rs`, `commands/remote.rs`, and pill reducer checked. No builds or runtime tests. Ranked by impact; line numbers refer to the beta.8 worktree.

1. [High] [security-privacy] `src-tauri/src/remote/client.rs:255-259` — `format_base_url` unconditionally produces `http://`; `remote/lifecycle.rs:292-321` binds the warp server on non-loopback interfaces without TLS, while `client.rs:601-615` sends the password header, context and raw WAV over that connection. Any LAN observer can read credentials/dictation and impersonate a peer → add authenticated encrypted transport (TLS with a paired/trusted host identity, or equivalent), not merely a password on plaintext HTTP → effort L.
2. [High] [security-privacy] `src-tauri/src/whisper/cache.rs:69-85` — `get_or_create` logs `model_path` and a cache key containing its full path, again at `:87-106` and eviction `:154-162` including `log_with_context("model_path", &key)`; `whisper/manager.rs:294` logs the output path, and `transcription/executor.rs:88-95` logs the input audio path on deletion failure. This violates the explicit AGENTS.md no-path-in-logs invariant → replace all such logs with a closed model ID or generic operation/error code; remove full paths from context payloads → effort S.
3. [High] [bug-risk] `src-tauri/src/remote/http.rs:203-222` — `warp::body::bytes()` buffers up to 512 MiB *before* the single transcription permit; each concurrent authenticated request (or every request on the default passwordless server) can allocate its own body, and stalled uploads have no read deadline because the one-hour timeout begins only at `:769`. Many simultaneous slow uploads can exhaust host RAM even though one transcription is permitted → stream to size-limited temp files with upload deadline and global upload admission/budget, acquiring admission before body read but keeping engine serialization separate → effort L.
4. [High] [bug-risk] `src-tauri/src/cloud_stt/soniox.rs:1299-1339` — the upload POST is wrapped in `common::with_retry`, which retries network/timeouts/5xx (`common.rs:183-197`) despite a non-idempotent Files endpoint. If the first upload succeeds server-side but its response is lost, a second upload is created and only the second returned ID is registered at `soniox.rs:1340-1350`; the first audio file is never owned/deleted and accumulates against the storage quota. Diarized twin at `:1636-1678` → use an API idempotency key if supported; otherwise do not blindly retry ambiguous uploads, and provide a recoverable ownership/reconciliation mechanism → effort M.
5. [High] [bug-risk] `src-tauri/src/remote/http.rs:765-782` — the blocking engine task holds `ctx_for_blocking.blocking_read()` for its entire transcription; status and control handlers also require `ctx.read().await` (`:522-527`, `:479-485`). A long remote decode therefore freezes status probes and model-control requests despite separate HTTP tasks; the one-hour response timeout does not release this lock until the detached decode finishes → keep the immutable context in `Arc` and snapshot mutable model state independently, rather than holding the HTTP context lock across inference → effort M.
6. [High] [bug-risk] `src-tauri/src/cloud_stt/soniox_ws.rs:61-110` and `cloud_stt/deepgram_ws.rs:64-113` — each PCM `send_chunk` allocates `samples.to_vec()` into an unbounded MPSC queue while the socket connects/sends; `connect_async_tls_with_config(...).await` at `soniox_ws.rs:186-194`/`deepgram_ws.rs:215-223` has no explicit connection deadline. A stalled connection or slow downstream can retain an entire long recording in RAM, unlike Parakeet's bounded preview queue (`parakeet/sidecar.rs:20-32`) → bound queued audio and connection/write deadlines; on overflow invalidate WS-final authority and use the existing complete-WAV REST fallback → effort M.
7. [Med] [security-privacy] `src-tauri/src/remote/client.rs:635-644` — a non-2xx `/transcribe` body is stored verbatim as `HttpStatus.body`; `commands/audio.rs:1827-1829` writes `server_error_body()` into failed history. The schema/decode failures are deliberately redacted at `client.rs:277-285`, but a server that returns transcript text in a 4xx/5xx body leaks it into failure history (and passwordless LAN HTTP enables injected error bodies) → whitelist protocol error codes from JSON and redact all other remote body content; apply same treatment to auth errors → effort S.
8. [Med] [bug-risk] `src-tauri/src/remote/client.rs:457-480,512-533,558-579` — status and GET/PATCH model-control read `response.bytes()` with no response-size cap; only transcription goes through `read_capped_bytes` at `:623-629`. A faulty or hostile LAN peer can deliver an arbitrarily large status/control body within the 10-second timeout and exhaust client memory → use the existing capped streaming reader with small endpoint-specific limits for these endpoints too → effort S.
9. [Med] [duplicate] `src-tauri/src/cloud_stt/soniox.rs:1230-1354,1427-1526,1568-1685,1686-1788` — typed and diarized jobs duplicate quota self-heal, whole-file upload/registration, create/poll/extract and terminal cleanup with only the response projection and diarization flag differing. Changes to retries or cleanup must be applied twice (the `run_*` poll loops both hard-code 180 s) → one Soniox job lifecycle taking a result extractor/diarization mode; keep Soniox's ownership, quota classification and token/speaker extraction provider-specific → effort M.
10. [Med] [perf] `src-tauri/src/cloud_stt/soniox.rs:1199-1203,1300-1307,1542-1547,1637-1644` — the typed and diarized flows read a whole WAV into `Vec<u8>` and clone it on every upload retry before multipart construction; `cohere.rs:41-67` and `deepgram.rs:127-143,194-212` do the same for their uploads. Long files multiply peak memory even though `common.rs:366-448` already streams/reopens a file for OpenAI/Groq retry → factor a replayable streaming audio-body/multipart helper and use it for these adapters; providers retain auth, endpoint, form/query fields and response parsing → effort M.
11. [Med] [duplicate] `src-tauri/src/cloud_stt/soniox_ws.rs:39-110,152-283` and `cloud_stt/deepgram_ws.rs:40-113,156-330` — two near-parallel handle/control-channel, oneshot, task, TLS upgrade, PCM serialization, keepalive and cancellation loops; both also have near-duplicate sink construction and WS-final wiring in `commands/audio.rs:529-968`. There is no shared capacity/backpressure policy and only one stream is offered outside preview (`soniox` regular mode vs Deepgram preview-only). Extract a bounded WS session transport (queue, connect/write deadlines, terminal/cancel), and a common sink authority bridge; retain each provider's auth/config framing, URL params, response folder, keepalive frame and completion signal → effort L.
12. [Med] [oversized] `src-tauri/src/cloud_stt/soniox.rs:1-1828` — 1,828 production lines contain at least four separable concerns: scoped ownership/active-job ledger (`:47-239`), account listing/delete/manual and auto cleanup (`:241-1155`), typed and diarized transcription flows (`:1156-1807`), plus 2,795 in-file test lines beginning `:1829`. Split into `ownership`, `storage`, `job` and an adjacent test module/files around the existing private API; do not generalize Soniox-specific quota recovery into other providers → effort M.
13. [Med] [oversized] `src-tauri/src/remote/http.rs:1-834` — production route composition/auth (`:122-480`), status/model-control (`:479-638`), and transcription/body/engine task (`:639-834`) sit above 2,147 in-file test lines starting `:835`. Move tests to existing `remote/integration_tests.rs`/focused route tests and split route/auth/transcribe handlers, preserving one `ServerContext` interface and one auth primitive → effort M.
14. [Med] [drift] `src-tauri/src/transcription/executor.rs:121-140,333-342` — the claimed single `transcribe_with_app` contract explicitly rejects `EngineSelection::HostDefault` and `Remote`; desktop `commands/audio.rs:6334-6450` branches around it for WS authority and remote client, while inbound `remote/transcription.rs:283-347` has another engine switch with a default-to-Whisper catch-all. `transcription/stream.rs:125-146` separately defines preview capabilities and `provider_capabilities.rs:60-120` defines request capabilities. This is several partial abstractions, not a universal engine port: timeout/normalization, context, translate support, preview and remote execution policies leak into callers → complete one `TranscriptionRequest` execution boundary for desktop/CLI/inbound where feasible, make remote selection explicit rather than fallback, and keep preview as an explicit sidecar capability instead of pretending all providers stream → effort L.
15. [Med] [bug-risk] `src-tauri/src/remote/transcription.rs:307-335` — inbound `transcribe_inner` dispatches only `"parakeet"`, treating every other engine string as Whisper; `remote/model_control.rs:26-90` currently lists only shareable Whisper/Parakeet, but the server accepts an engine string at `remote/lifecycle.rs:191-231`. A bad/stale engine value is silently decoded using the Whisper model path and mislabeled with the requested engine → reject unknown engine values at the inbound dispatch and server-start/update boundaries → effort S.
16. [Med] [bug-risk] `src-tauri/src/whisper/manager.rs:297-304,335-359` — model downloads construct `reqwest::Client::new()` and stream `bytes_stream()` without an explicit request or stalled-chunk timeout; the Windows ONNX downloader explicitly bounds each network operation with `STALL = 30s` (`parakeet/onnx/download.rs:18,307-331`). A server that stops sending after HTTP headers leaves Whisper download waiting indefinitely absent user cancellation → add a stall deadline reset on progress plus a connection deadline while keeping multi-GB transfers viable → effort S.
17. [Low] [perf] `src-tauri/crates/transcript-text/src/lib.rs:28-71` — `normalize_spacing` allocates a `String::with_capacity(input.len())` before deciding whether the result equals the input, despite promising `Cow::Borrowed` for clean input. Every ordinary Whisper transcript in `whisper/transcriber.rs:791` incurs an avoidable full allocation/copy to discover no change → scan to first necessary rewrite and allocate/copy only from there → effort S.
18. [Low] [drift] `src-tauri/src/cloud_stt/mod.rs:59-108` — five cloud model catalogs are baked into Rust, including versioned Cohere ID `cohere-transcribe-03-2026`; `:180-204` falls back to default if stored ID is invalid. Retired provider IDs will require app releases and can silently change the executed model for saved settings → periodically validate catalogs against provider listing at release time and surface unavailable selected models rather than silently switching, while retaining a curated/pinned allowlist → effort M.
19. [Low] [drift] `src-tauri/src/parakeet/models.rs:105-239` — CoreML catalog records mutable Hugging Face repo IDs and estimated sizes, unlike immutable SHA-256/revision pins for Windows ONNX at `parakeet/onnx/download.rs:18-56` and Whisper at `whisper/manager.rs:98-169`; `parakeet/manager.rs:282-284` even exposes an empty SHA field. Upstream repo changes can alter what the same model ID downloads without a locally auditable manifest → pin Swift/FluidAudio download revision and expected asset checksums (or versioned manifest) when the sidecar exposes the artifact list → effort M.

## Best payoff per effort
1. Remove path-bearing logs in Whisper cache/manager and executor (S; explicit invariant).
2. Cap status/control response bodies and redact all remote error bodies (S; client robustness/privacy).
3. Add hard admission/upload deadlines to remote HTTP body collection (L, but protects host memory on default-open LAN service).
4. Replace Soniox ambiguous upload retry with idempotent/reconcilable ownership (M; avoids storage-quota leaks).
5. Bound the cloud WS audio queues and connect/write operations (M; prevents slow-network RAM growth without blocking capture).

## Not covered / limitations
No runtime handshake or hardware speech tests, actual cloud account behavior, provider API verification, dynamic profile/memory measurements, or exhaustive line-by-line review of Swift sidecar, UI, `commands/audio.rs`, or all 2k+ remote/Soniox tests. No `ffmpeg*` files appeared under `src-tauri/src`; repository architecture says audio decoding is pure Rust. No dead engine or capability with zero production callers was proven: all five cloud providers dispatch in `cloud_stt/mod.rs:291-310`, and the explicit EOU dormant paths are documented as intentionally retained. Findings on future model-catalog drift are maintenance risks, not externally verified provider breakages.
