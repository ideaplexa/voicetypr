# Appcore audit — release/2.1.0-beta.8

Read-only static review of `lib.rs`, CLI, commands except audio.rs (consulted only as a consumer), writing, AI, licensing, secure storage, telemetry/analytics, capabilities and Tauri config. No build/tests were run. The worktree has no uncommitted diff in this target; these are current-code audit findings, not patch-introduced review findings. Evidence paths are relative to the worktree.

## Ranked findings

1. [High] [security-privacy] src-tauri/src/ai/agent_cli/private_input.rs:177-183 — OpenCode 1.x uses `InputMode::PositionalArg`, and `command.arg(input_text)` places dictated text in the child process command line (the spec selects this mode at `ai/agent_cli.rs:317-335`); other local processes/process inspection can see the transcript even though prompt handling uses private files → use an input transport not exposed in argv, or do not offer that adapter when impossible → effort M.
2. [High] [security-privacy] src-tauri/src/commands/debug.rs:55-61 — registered `test_transcription_event(app, text)` logs `"... with text: '{}'"` verbatim; it remains reachable through the invoke registry (`lib.rs:1272-1273`) despite zero non-test `src/` references for its name → remove the exposed test command and its registration; never log the text → effort S.
3. [High] [security-privacy] src-tauri/src/lib.rs:756-767 — setup logs the absolute `models_dir` at Info and passes its formatted path to `log_with_context` and `log_file_operation`; release `setup_logging` sends Info to stdout and LogDir (`lib.rs:370-395`). Other concrete path leaks: `commands/utils.rs:74-80,94-95` logs export/save paths, `commands/clipboard.rs:128` logs the image target, `commands/logs.rs:365` logs the log path. Bug-report redaction occurs only when reading attachments (`commands/logs.rs:375`), not before local logging → replace path-bearing operational messages with fixed operation/category/status and scrub before all sinks → effort M.
4. [High] [security-privacy] src-tauri/src/commands/ai.rs:774-780 — failed `test_openai_endpoint` logs the complete user-supplied `base_url` and `model`; `validate_custom_base_url` only checks scheme/link-local host (`ai.rs:250-272`), so URLs with credential userinfo or private query/path reach the Info/Error log unchanged. Another custom-endpoint error logs the URL at `ai.rs:1377-1382` → log a fixed failure category, not endpoint strings → effort S.
5. [Med] [bug-risk] src-tauri/src/commands/settings.rs:857-876 — `save_settings` rewrites the whole form, while `SettingsContext.updateSettings` sends a whole optimistic snapshot (`src/contexts/SettingsContext.tsx:58-90`) and concurrent calls aren't serialized. Since `save_settings` awaits source normalization (`settings.rs:861-867`) before writing and awaits saving later, two quick independent updates can complete out of order, with the earlier snapshot overwriting a later setting; out-of-band AI writes to `transcription_task`/`final_text_language` (`commands/ai.rs:927-933`) present the same stale-snapshot risk before the refresh event is processed → accept validated partial settings patches (or serialize/merge on the backend), preserving fields untouched by each caller → effort M.
6. [Med] [bug-risk] src-tauri/src/commands/settings.rs:998 — every generic settings save deletes `sharing_password` from the legacy settings store. If startup migration cannot write the password to `secure_store`, `load_remote_settings` explicitly leaves the legacy value in place (`commands/remote.rs:1760-1782`); a later ordinary settings save then destroys the only copy, disabling password-protected sharing after restart → delete the legacy key only after confirmed secure-store migration, not from generic save → effort S.
7. [Med] [bug-risk] src-tauri/src/commands/settings.rs:1000-1020 — a generic save changes `RemoteSettings.server_config.port` in memory and saves `voicetypr-store.json` before it persists the separate `settings` store; failure of either save leaves a partial change (the earlier `store.set` calls are already in the shared store cache, while `persist_generic_settings` reloads only on its own save failure at `settings.rs:74-78`). A failed Settings UI save can therefore leave remote port and bulk settings disagreeing → stage/commit with rollback on either failure, or make the port's owning store the single source and write it independently → effort M.
8. [Med] [security-privacy] src-tauri/capabilities/default.json:5-34 — the same default capability applies to both `main` and `pill` and grants `store:default`, `core:webview:allow-create-webview-window`, `fs:scope-appdata`, `shell:allow-open`, updater download/install, process exit/restart, and window creation. The pill is a renderer for recording feedback, not a settings/update/file-management surface (`src/pill/renderer.ts`, `AGENTS.md:39`); a compromised pill webview inherits these unrelated operations → split main/pill grants, restrict the pill to the few APIs its source actually uses and drop unused direct plugin grants (the frontend search found no production plugin-store or plugin-fs imports) → effort M.
9. [Med] [oversized] src-tauri/src/ai/agent_cli.rs:101-166 — this 4,034-line root module owns provider flags/policies, argv assembly (`:430`), process-group timeout/drain (`:603-900`), output parsers (`:1137-1368`), PATH/shell discovery (`:1387-1641`), and provider model discovery (`:1765-2400+`), despite existing child modules for hot spare/invocation/private input. Changing a CLI contract currently touches unrelated parsing, spawn, discovery and tests in one file → split provider specs, process transport, parsers, binary resolution and model listing behind existing `agent_cli` module; retain one dispatch owner → effort L.
10. [Med] [drift] src-tauri/src/commands/settings.rs:877-885 — every save still dual-writes retired `language` and `translate_to_english` instead of migrating once. Parallel legacy fallbacks remain at `writing/pipeline.rs:201-205`, `commands/remote.rs:1562-1567`, `lib.rs:1685-1687`, and `commands/audio.rs:4107-4115,7796-7803`; `show_pill_indicator` is also read at `lib.rs:962` even though `save_pill_indicator_mode` deletes it (`settings.rs:1519-1522`). Permanent parallel key schemes make a newly added call path easy to normalize differently → do one versioned startup migration and remove legacy keys/read paths after establishing canonical values → effort M.
11. [Low] [dead-code] src-tauri/src/lib.rs:1272-1276 — registered `debug_transcription_flow`, `test_transcription_event`, `get_current_audio_device` have zero production frontend `src/` references; same for `get_supported_languages` (`:1302`), `test_automation_permission` (`:1348`), `get_log_directory`/`open_logs_folder` (`:1391-1392`), `refresh_remote_servers` (`:1437`), and `disable_ai_enhancement` (`:1374`). Reference search in backend found only definitions/registry for the debug/test/permission commands, while `get_supported_languages` has a test caller; `refresh_remote_servers` merely returns cached list (`commands/remote.rs:970-976`). Other registered commands are invoked dynamically by the pill or from Rust and must not be pruned from a literal-invoke diff alone → remove confirmed dead public commands and registry entries; keep test helpers private where needed → effort S.
12. [Low] [drift] src-tauri/src/commands/settings.rs:136-137 — `Settings` still exposes `sharing_password`, but `get_settings` hardcodes `None` (`:676`), `save_settings` ignores the value and deletes its store key (`:998`), and production frontend only carries the field in `src/types.ts:162` (reference search found no non-test read/write). This misleading API suggests setting the password via bulk settings succeeds and unnecessarily transfers a secret if a caller does so → remove the field from Rust/TS bulk settings and keep remote password commands as sole owner → effort S.
13. [Low] [oversized] src-tauri/src/lib.rs:629-1259 — setup closure contains encryption/identity, log cleanup, model/remote state, sharing restoration, window/tray and startup tasks, while command registration (`:1259-1441`) and ordered exit teardown (`:1507-1538`) share the 1,915-line crate root. The invariant-critical teardown should remain an explicitly ordered single call; move cohesive bootstrap steps to small named init functions/modules and command import/registration bookkeeping to a dedicated bridge module, avoiding logic changes → effort M.

## Five best payoff / effort

1. Remove `test_transcription_event` from release IPC and its plaintext transcript log (S).
2. Stop logging custom AI endpoint URLs/models on failure (S).
3. Delete legacy `sharing_password` only on successful secure-store migration (S).
4. Remove absolute-path log arguments from bootstrap and save/export commands (M).
5. Change whole-struct settings saves to validated touched-key patches (M).

## Not reached / constraints

I did not validate runtime hardware behavior, Windows/macOS permission behavior, remote API responses, provider-specific CLI versions, or license server semantics. I found no evidenced frontend literal invoke missing from the Rust registry: the only unmatched literal was Tauri's plugin route `plugin:opener|open_url`; pill commands use dynamic names, so the initial literal-only comparison overstated unused registrations. I did not assert that offline licensing is bypassable or blocks legitimate paid users: the inspected paid-license code explicitly has a 90-day offline grace (`commands/license.rs:64,275-318`). I found no proven duplicate writing stage or unused AI provider/preset in this static slice; those require more path-by-path runtime contract validation rather than inference from file size.
