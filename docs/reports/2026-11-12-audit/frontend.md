# Frontend audit — release/2.1.0-beta.8

Read-only static audit of `src/**`, entry/build/test configuration, and package imports. No build or tests run. The working-tree `git diff` was empty; these are current-code findings, not patch-introduced regressions. Ranked by impact/payoff, not a claim that every historical source file was exhaustively dependency-graphed.

1. [High] [bug-risk] `src/contexts/SettingsContext.tsx:84-96` — `updateSettings` sends a full `nextSettings` snapshot to `save_settings` for each optimistic edit; two rapid edits send A and A+B concurrently. Rust's `save_settings` writes all keys and awaits during persistence (`src-tauri/src/commands/settings.rs:872-895`), so an older save completing later can overwrite the newer edit on disk while the React ref still shows A+B; failed older saves also revert touched keys without checking for a newer edit to that same key (`SettingsContext.tsx:131-138`). → Serialize/coalesce full-snapshot saves and gate rollback/publish by revision (or make backend patch updates atomic) → effort M.
2. [High] [bug-risk] `src/hooks/useRecording.ts:58-115` — The sequential `await listen(...)` calls continue after the effect's cleanup; cleanup only disposes functions already in `unsubscribers`. Under React StrictMode remount, the first pending registration resolves after unmount and remains active, duplicating state updates and keeping an old mounted closure alive. → Use disposed flag with immediate disposal of each late listener, or the established `useTauriEvent` pattern → effort S.
3. [Med] [bug-risk] `src/hooks/useTranscriptionHistory.ts:125-153` — Initial `setup` awaits `refreshHistory()` before subscribing to `transcription-added`, `history-updated`, and `transcription-updated`; an upload/dictation finishing while the 10,000-row history request is in flight is not guaranteed to be in its snapshot and has no listener yet. The Recordings screen then remains stale until another event/manual refresh (`RecordingsTab.tsx:20-25`). → Subscribe before the initial fetch, then reconcile event and snapshot ordering → effort M.
4. [Med] [perf] `src/components/sections/useRecentRecordings.ts:51-81` — Each history refresh runs one `check_recording_exists` IPC/filesystem query per row with `recording_file`, all at once via `Promise.all`, although only 60 results are initially visible (`useRecentRecordings.ts:44-47`); `RecordingsTab.tsx:20-24` loads up to 10,000 rows. Backend command does path resolution and `.exists()` per request (`src-tauri/src/commands/audio.rs:8205-8213`). → Batch existence checks in one backend command or check only visible/expanded rows with cache → effort M.
5. [Med] [bug-risk] `src/components/sections/network-sharing/useSharingStatus.ts:145-176` — `fetchStatus` logs a failed `get_sharing_status` and leaves the default `{enabled:false}` (lines 20-30) or the last successful status visible. If backend is unreachable, UI can present a false “off” state instead of an error and enable misleading controls. → Track fetch error/unknown state and expose it in both network-sharing surfaces → effort S.
6. [Med] [bug-risk] `src/hooks/useRecording.ts:39-53` — The `get_current_recording_state` response unconditionally applies after it returns; an intervening `recording-state-changed` event can update to recording, then an older snapshot restores idle. This hook drives in-app hotkey behavior (`src/hooks/useInAppRecordingHotkey.ts:109-110`). → Register listener first and gate initial snapshot against events/generation → effort S.
7. [Med] [bad-practice] `src/components/polish/useAiProviderSettings.ts:268-373` — Four `listen` promises are joined in cleanup with `Promise.all(...).then(...)`; one failed registration rejects the join, preventing disposal of the other successful listeners and leaving a rejection unhandled. The callback also awaits settings IPC without a disposed guard. → Dispose each settled subscription independently, handle registration errors, and ignore late callbacks → effort S.
8. [Med] [bug-risk] `src/components/sections/network-sharing/ConnectionSettingsPanel.tsx:227-234` — The password visibility button in the non-pane branch has `tabIndex={-1}`; the branch is live through `NetworkSharingTab.tsx:11` → `NetworkSharingCard` default `pane=false`, so keyboard-only users cannot reveal/rehide the password. Pane branch's equivalent button has no negative tab index (`ConnectionSettingsPanel.tsx:84-89`). → Restore normal tab order → effort S.
9. [Med] [oversized] `src/components/polish/useAiProviderSettings.ts:54-77` — The 711-line hook owns provider discovery, key cache hydration (`:129-215`), CLI probing (`:91-127`), four event subscriptions (`:268-373`), and selection/toggle actions (`:413-711`). Changes to one lifecycle obscure another; splitting at provider discovery/CLI probe vs selection mutation is a concrete seam while keeping one owner for AI settings state → effort M.
10. [Low] [duplicate] `src/components/sections/NetworkSharingCard.tsx:112-161` — The pane branch reimplements firewall status/open/recheck controls already in `src/components/sections/network-sharing/SharingControls.tsx:99-184` for the non-pane branch; both are live (`SettingsTab.tsx:161` vs `NetworkSharingTab.tsx:11`), so fixes/copy can diverge. → Extract the shared firewall behavior/status presentation and compose variant layouts → effort S.
11. [Low] [duplicate] `src/components/tabs/OverviewTab.tsx:48-51` — Overview separately fetches `get_ai_settings` and `get_enhancement_options`, while Polish loads those through `useAiProviderSettings` and `usePolishSectionSettings` (`EnhancementsSection.tsx:79-95`); `ModelOptions.tsx:38-42` separately fetches AI enabled again. These screens hold independent snapshots of the same backend values, with no shared invalidation on AI changes. → Centralize the minimal Polish summary in one subscribable state source or refresh on its backend change events → effort M.
12. [Low] [dead-code] `package.json:41` — `@tauri-apps/plugin-autostart` has no production import: the repository reference search returned only this declaration and mocks/import in `GeneralSettings.*.test.tsx` / `RecordingSettings.*.test.tsx`, while real autostart uses backend `get_autostart_status` / `set_autostart` (`src-tauri/src/commands/settings.rs:1648-1661`; `AppBehaviorCard.tsx:77-122`). → Remove frontend package and obsolete test mocks after checking lockfile → effort S.
13. [Low] [dead-code] `src/contexts/ReadinessContext.tsx:49-53` — `useCanRecord` is exported but the non-test reference search returned only its declaration, whereas consumers use `useReadiness`/`useReadinessState` (`AppContainer.tsx:54`, `EnhancementsSection.tsx:21`). → Remove unused convenience export → effort S.
14. [Low] [bad-practice] `src/hooks/useEventCoordinator.ts:32-35` — `registerEvent<T = any>` and `EventCoordinator.ts:8,46` default to `any`, violating AGENTS.md strict-TS no-`any`; `useRecording.ts:64-67` also accepts `(event: any)` despite `RecordingStatePayload` in `src/types.ts:82-86`. → Default unknown and type the recording payload, removing unchecked access → effort S.
15. [Low] [test-noise] `src/components/sections/__tests__/EnhancementsSection.test.tsx:1282-1352` — The giant suite has a duplicate hierarchy-only test (compare `:543-571`), a test that reads source files to assert a type declaration's location (`:1313-1340`), and a test asserting an already-deleted `ProviderCard.tsx` stays absent (`:1341-1352`); these lock implementation layout rather than regressible user behavior. → Drop/replace those with focused behavior coverage; keep key validation, writing-save ordering/rollback (`:1489-1678`), and failure-banner tests (`:2026+`) → effort S.
16. [Low] [test-noise] `src/components/sections/__tests__/NetworkSharingCard.test.tsx:136-274` — Separate giant fixtures repeat a switch for every command and include stale `get_settings` fields (`current_model:null`, `auto_insert:true`, lines 139-145) unlike Rust `Settings` (`settings.rs:85-100`); trivial wording/absence tests (`:248-273`, `:1324-1355`) mostly exercise mock fixtures. → Use typed shared fixtures and collapse copy assertions; keep invalid-port rejection (`:1513-1550`), unsaved-port address (`:972-996`), and failed-restart restoration (`:1553-1682`) → effort M.
17. [Low] [duplicate] `src/App.tsx:12-16` — `ThemeSync` calls side-effectful `useTheme`, and `AppToaster.tsx:5-7` calls it again; each hook installs a system-theme media listener and toggles the root `.dark` class (`useTheme.ts:30-47`). → Separate theme synchronization from resolved-theme reading, or pass resolved theme from a single owner → effort S.

Dependency sweep: production imports/entry/config references were found for Base UI, both Geist packages, Tailwind/Vite, Tauri API and dialog/log/notification/OS/process/shell plugins, CVA, cmdk, cnfast, lucide, next-themes (inside vendored sonner primitive), React/DOM/error-boundary/markdown, sonner, and zustand. The only unused production package evidenced by the reference search is frontend autostart. Dev packages are referenced by scripts, config, tests, CSS, or release scripts (notably `playwright-core` in `scripts/ui-preview/shoot.mjs`, `shadcn` in `globals.css`, and conventional-changelog in `scripts/release-separate.sh`). `vite.config.ts:16-22` declares both main/pill entrypoints, `index.html:10-11` mounts main, and `pill.css:24` retains the `[hidden]` invariant. Frontend `AppSettings` keys were spot-checked against Rust `Settings` (`types.ts:121-172`, `settings.rs:84-155`); `ptt_hotkey` and `sharing_port` are optional but omit Rust's nullable type; no unsafe use proven, so not raised as a defect.

## Five best payoff/effort
1. Fix late-listener disposal in `useRecording`.
2. Subscribe to history events before initial fetch.
3. Expose sharing-status fetch failures instead of defaulting to “off”.
4. Restore keyboard access to the password eye button.
5. Remove unused frontend autostart dependency and test mocks.

## Not covered / limits
No dynamic Tauri/hardware behavior or test/build execution; no exhaustive importer graph for every `src/components/ui/*` generated primitive or every exported type; no git-history check of edits to generated UI primitives. No screenshot-based aesthetic critique: UX findings here are source-evidenced interaction defects, not visual judgments. No verified transcript/audio/prompt/key/path/window-title leak in frontend logs was found during the targeted search, so none is alleged. `git diff` had no changes to review as a patch.
