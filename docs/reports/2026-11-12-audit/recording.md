# Recording/audio/hotkey audit — release/2.1.0-beta.8

Read-only static review; paths and lines are relative to the beta8 worktree. No build, tests, or hardware smoke were run. Ranked owner-actionable findings follow.

1. [High] [security-privacy] `src-tauri/src/lib.rs:756-771` — Startup writes the absolute `models_dir` to `log::info!`, `log_with_context`, and `log_file_operation` (`"Models directory: {:?}"` at 757). This happens on every ordinary launch and violates the repository rule that paths never enter logs; debug `.env` discovery also calls `log_file_operation` with its path at 554-558 → remove/redact path-bearing log fields at the logging boundary → effort S.
2. [High] [bug-risk] `src-tauri/src/commands/audio.rs:7717-7742,7922-7934` — A successful diarized Soniox/Deepgram upload returns `UploadTranscription` before the sole `writing::process_transcription_at` invocation at 7993-8004. Thus uploads that happen to have speaker words bypass vocabulary, library rules, output-language transform, and optional Polish; `src/state/upload.ts:86-115` persists returned text without another writing pass → turn the diarized result into `TranscriptionResult` and run the common writing stage, preserving words/metadata → effort M.
3. [High] [perf] `src-tauri/src/commands/audio.rs:5510-5561` — The async stop command calls synchronous `recorder.stop_recording_with_post_roll` while holding `RecorderState`'s `std::sync::Mutex` (`:5530`); `audio/recorder.rs:1210-1251` polls/sleeps up to `STOP_JOIN_TIMEOUT` (8 seconds), and cancellation needs the same lock (`commands/audio_cancel.rs:48-58`). A slow device/writer blocks a Tokio worker and queues cancellation behind teardown → run stop/join under `spawn_blocking`, returning stop result and metrics before async continuation → effort M.
4. [High] [perf] `src-tauri/src/commands/audio.rs:4274-4287` — Persisting a recorded WAV invokes `std::fs::copy` synchronously in the spawned async transcription task (`:4282-4285`), with a second copy at 4335-4343. Remote desktop/upload also synchronously load full WAVs at 6397-6400 and 7868-7870. Long files or stalled disks block runtime workers even though normalization already uses `spawn_blocking` at 6077-6085 → move disk copy/read to blocking workers, preserving generation checks around completion → effort M.
5. [High] [perf] `src-tauri/src/commands/audio.rs:624-629,808-813` — The Soniox/Deepgram tap worker forwards every frame via `send_chunk`, which does `samples.to_vec()` into an **unbounded** Tokio channel (`cloud_stt/soniox_ws.rs:59-69`, `deepgram_ws.rs:62-72`). Its nominal 256-frame stream-tap bound is ineffective after this transfer: a socket that consumes slower than capture can buffer a long recording in RAM alongside the WAV → bound cloud chunk queues; on backpressure invalidate WS authority and use complete-WAV REST fallback → effort M.
6. [Med] [security-privacy] `src-tauri/src/commands/audio.rs:5817-5824,6391-6396,7859-7866` — Desktop remote selection, remote transcription, and remote upload directly log user-defined server display names plus host/port (`"Using remote server for transcription: {} ({}:{})"` at 5818). Hostnames and names identify users and their LAN topology → log only closed transport/error categories and timings; remove equivalent messages in `commands/remote.rs`/CLI → effort S.
7. [Med] [security-privacy] `src-tauri/src/audio/device_watcher.rs:103-104,140-147` — Every device-change log dumps the full microphone-name vector (`"Audio devices changed: {:?}"`), and fallback logs selected labels. The recorder also logs the selected device at `audio/recorder.rs:644-650`, while start logs microphone selection at `commands/audio.rs:5130-5142`. These host/user-identifying labels are unnecessary in durable diagnostics → log count and change classification instead → effort S.
8. [Med] [bug-risk] `src-tauri/src/commands/audio.rs:1097-1113,7443-7461` — `persist_if_current` tests an atomic cancellation/generation snapshot but does not serialize it with the synchronous `store.set`/`store.save`. A cancel on another thread can land *during* save; history commits at 7393-7479 and 7493-7557 do not have the post-save revoke that recorded-audio copies have at 6488-6501. This can leave cancelled text in history → serialize cancellation with commit or recheck after save and remove the row/update the index if revoked → effort M.
9. [Med] [bug-risk] `src-tauri/src/commands/audio.rs:7717-7723,7922-7943` — Every Soniox/Deepgram upload first runs a full cloud diarization request. If it succeeds without `words`, the branch discards even a non-empty `cloud_transcript.text` and falls through to `transcribe_with_app` at 7976, submitting a second paid request for the same audio → reuse the successful plain transcript as the normal writing-stage input (or request diarization only when needed) → effort S.
10. [Med] [bug-risk] `src-tauri/src/commands/audio.rs:4476-4514` — `get_recording_config` loads settings via `RecordingConfig::load_from_store(...).await` outside the cache write lock, then stores the result unconditionally (`:4507-4513`). If settings invalidation writes `None` while the load awaits language normalization (`:4165-4172`), the old result can repopulate the cache for five minutes → publish only when an invalidation version is unchanged, or serialize load and invalidation → effort M.
11. [Med] [bug-risk] `src-tauri/src/recording/hotkeys.rs:76-85,203-215` — Spawned toggle/PTT starts unconditionally call `update_recording_state(Error, ...)` when their async start returns `Err`. Owner-aware `fail_start` already publishes the error (`commands/audio_start.rs:254-302`); an older callback that runs after a replacement generation starts can force the newer recording into Error (`state/app_state.rs:243-271`) → leave error publication to the start command, or gate the hotkey update against its captured generation → effort S.
12. [Med] [duplicate] `src-tauri/src/cli.rs:850-897` — CLI `--server` constructs a separate remote request and invokes `writing::process_transcription`, while CLI local delegates to `transcribe_audio_file_for_cli` (`cli.rs:519-538`, `commands/audio.rs:7667-7688`). Shared `resolve_transcription_task_for_audio` at `audio.rs:2214-2227` forces Transcribe in personal-dictation mode, but CLI remote passes `settings.transcription_task` directly at `cli.rs:863-873`; the same setting can therefore translate only on CLI remote → share task resolver/request construction and writing contract, retaining distinct CLI output → effort M.
13. [Med] [bug-risk] `src-tauri/src/audio/device_watcher.rs:115-159` — Each 1.5-second snapshot spawns an independent async task carrying its `devices_for_tasks`. A delayed task for an unplugged device can clear `selected_microphone` after a newer snapshot observes its reattachment; no fresh device check occurs immediately before `set_audio_device(..., None)` → serialize updates or re-enumerate/recheck against live devices before clearing preference → effort M.
14. [Med] [security-privacy] `src-tauri/src/commands/audio.rs:7554-7558` — Failed transcription history logs the exact `recording_file` filename (`"Saved failed transcription with recording file: {}"` at 7556); raw failure messages are also logged at 6120/7210, and failed filesystem operations may carry paths. The repository prohibits paths in logs → replace file identifiers and unfiltered error strings with status/error classes → effort S.
15. [Low] [dead-code] `src-tauri/src/commands/audio.rs:4065-4074,4141-4165` — `RecordingConfig` reads `ai_provider`, `ai_model`, and `show_recording_status`, but a reference search over `commands/audio.rs` found no non-test consumers beyond construction; `final_text_language`/`ai_enabled` are only logged at 5076-5081/6217-6223. These fields make the cache look authoritative over writing settings although writing reads its own configuration → delete dead cached fields/reads, or wire them if needed for real behavior → effort S.
16. [Low] [dead-code] `src-tauri/src/audio/stream_tap.rs:14-19,54-59` — `StreamTapMsg::Cancel` and `StreamTapRt::dropped()` are explicitly `#[allow(dead_code)]` for future work; reference search shows `Cancel` construction only in tests (`:591`) and `dropped()` only in tests (`:575,631`). Real cancellation uses the closure/flag at 322-355 → remove dead production variant/accessor and test actual cancellation path → effort S.
17. [Low] [test-noise] `src-tauri/src/commands/audio.rs:2139-2163,3439-3503` — `ai_failure_notice` is `#[cfg(test)]` only; multiple tests assert its exact wording/length, while shipped failure payloads use `user_facing_message` through `ai_failure_payload` at 2158-2163. The tests can pass when production wording breaks or fail when only unused wording changes → delete the test-only formatter and test production payload category/privacy semantics → effort S.
18. [Low] [test-noise] `src-tauri/src/commands/audio.rs:2199-2212,2834-2888` — `plan_desktop_writing_success` hard-codes `save_history_entries: 1` and `should_deliver: true`, and the test titled `desktop_ai_polish_failure_delivers_saves_once_and_emits_failure` merely checks those constants on a hand-built `WritingResult`; it never invokes delivery, persistence or event emission → replace it with a task-level regression test for these side effects or remove the misleading claims → effort M.

## Responsibilities and concrete split seams

`commands/audio.rs` has **at least 11 production responsibilities** in 8,585 lines, plus ~1,770 lines of inline tests. Preserve the public Tauri command signatures but extract: (1) four live-preview adapters/factories `113-977` → `commands/audio_preview/{parakeet,whisper,soniox,deepgram}.rs`; (2) generation, cloud WS-final, in-flight audio ownership, journey guards `978-1325` → `recording/session.rs`/`recording/cloud_final.rs`; (3) history status/reconciliation/dedup `1405-1624` → `commands/transcription_history.rs`; (4) failure classification and remote/result construction `1625-2040` → `transcription/desktop_result.rs`; (5) writing metadata/AI feedback planning `2041-2299` → `writing/desktop_delivery.rs`; (6) inline tests `2300-4060` → seam-specific test modules; (7) config/cache/license and saved-WAV persistence `4061-4655` → `recording/config.rs`, `recording/saved_audio.rs`; (8) pending-stop, silence, island and start orchestration `4656-5408` → `recording/start.rs`, `recording/silence.rs`; (9) the **~1,850-line single** `stop_recording_with_mode_at` `5425-7271` → `recording/stop.rs` with separate capture finalization, engine selection, recognition, writing/delivery and failure finalizers, sharing one typed outcome; (10) devices/history CRUD `7272-7646,8089-8398` → `commands/audio_devices.rs` and history module; (11) file/CLI/upload/diarization `7647-8083` → `commands/file_transcription.rs`. Existing `audio_start.rs`/`audio_cancel.rs` are precedent; move shared primitives without creating parallel conventions.

## Repeated pipeline inventory (differences matter)

- Desktop mic: `commands/audio.rs:4941-5408` capture; `5425-6280` stop/normalize/select; `6281-6635` decode; `6640-7048` write/paste-or-copy/history. Unique generation, cancel, WS-final authority, pill/telemetry, and optional WAV save.
- GUI file upload: `audio.rs:7647-7666,7744-8051` normalize/select/decode/write and return; `src/state/upload.ts:86-116` writes history. No paste/recording lifecycle; diarized result currently bypasses writing.
- History re-transcribe: `src/components/sections/useRecentRecordingsActions.ts:70-147` saves placeholder, calls `transcribe_audio_file` (`audio.rs:7744-8051`) or `transcribe_remote` (`commands/remote.rs:1498-1623`), and updates the row. No paste; failure text replaces placeholder.
- Kept/recovery retry: `recording/kept.rs:1254-1352` delegates recognition/writing to `audio::transcribe_audio_file_impl(..., Some(generation))`, then saves history and pastes or copies with lease/cancel semantics.
- CLI local file and CLI mic: `cli.rs:505-539,577-651` delegate to `audio.rs:7667-7688,7744-8051` and print; no history/paste, unique temporary capture/retry retention.
- CLI remote: `cli.rs:845-897` called by both CLI routes (`:515-520,:625-630`), separately normalizes → remote request → writing → print, differing in task selection.
- GUI remote file: `commands/remote.rs:1498-1623` separately normalizes/reads/requests/writes. Desktop remote `audio.rs:6382-6456` separately reads/requests, then rejoins desktop delivery. Consolidate remote request/task resolution first, keeping destination-specific delivery.

## Five best payoff/effort changes

1. Remove path-bearing startup and recording-file logs (S; hard privacy invariant).
2. Route diarized cloud output through writing (M; correctness consistency).
3. Remove test-only `ai_failure_notice` and test actual payload (S; eliminates false coverage).
4. Delete unused config fields and stream-tap future-only code (S; less misleading state).
5. Move stop/join and saved-WAV copies onto blocking workers (M; protects runtime responsiveness).
