## 3. A. Windows Parakeet TDT v3

**Why:** usable large local dictation on low-end Windows CPUs, without a GPU. **Estimate:** 3–7 days,
excluding completed slices.

Read-only source: `feat/parakeet-windows-spike` at `6711e881`, worktree
`/Volumes/1tb-drive/developer/oss/worktrees/voicetypr-parakeet-win`. Its `plans/076-parakeet-on-windows.md`
records int8 ONNX, about 670 MB, `parakeet-rs =0.3.8`, static ORT, RTF 0.090 on four Windows vCPUs. That
implies about 0.9–2.7 s for 10–30 s, excluding load/decoding. Packaging, worker, download/delete and
catalog/UI slices 1–4 are implemented; slice 4 review remains. Slice 5 is Windows evaluation and installed-app
checks.

**Design/files:** retain `parakeet/onnx/{chunking,slot,session,download}.rs`, the manager façade and platform
capabilities from 076b. Finish review before integration. Compare identical normalized PCM on Mac and Windows:
the reported 39% versus 6% is **one French clip**, not French aggregate WER. Investigate resampling, channel
conversion and decoding before changing inference. Measure Windows peak RSS, cold load and warm runs on 8 GB
CPU-only hardware. Keep existing <=30 s chunks with quiet-gap boundaries and 15 s fallback; validate the 52 s
empty-single-pass regression and tail words. Check cancellation before/after load and between chunks; suppress
stale results and retain worker ownership until completion. In-flight native inference is not instantly
abortable.

**CLI first:** existing `voicetypr transcribe --file "$CLIP" --engine parakeet
--model parakeet-tdt-0.6b-v3 --json`; extend perf-harness for repeated/cancel runs.
**Acceptance:** no unexplained accuracy regression on matched PCM, warm RTF
<0.2 on the reference runner, measured peak RSS (076b target <2.5 GB), long
audio keeps boundary/tail words, cancelled results never paste. Verify static
linkage and download recovery. No vocabulary biasing, live preview or ARM64;
explain these gaps and offer Whisper fallback, never silently switch engines.
**NEEDS-SMOKE:** Windows 10/11 x64 NSIS and MSIX, offline install, clean machine,
low RAM, antivirus locks, interrupted downloads, cancel/delete/quit and model
switching. macOS: unchanged sidecar, preview, vocabulary and exit teardown.
**Risks:** young runtime, native cancellation delay, RAM pressure and PCM mismatch.

## 4. C. Context capture, on by default when Polish is on

**Why:** better names, grammar and insertion boundaries without user setup. **Estimate:** 12–18 days.

**Design/files:** proposed `context_capture/{mod,session,macos,windows,cli}.rs`, `ai/context_reference.rs`,
`writing/cursor_boundary.rs`. Dispatch a generation- owned async job at hotkey, after scheduling the Island
response; the Island must appear <50 ms and never await capture. Existing sync hint capture must move off that
path. Snapshot target process/window/element/range identity and recheck before use; cancel on stop/discard/new
generation, expiry or target change. Overall deadline 250 ms, AX calls capped at 50 ms. Timeout must discard
results without unbounded abandoned workers; prove how platform calls are bounded.

Statuses: `available`, `partial`, `disabled`, `secure`, `denied`, `unsupported`, `timeout`, `target_changed`.
Partial data is usable only if all security checks completed. Capture no clipboard or screenshots. Context
text stays ephemeral, never in History, logs, PostHog, `WritingResult` or `ContextHint`. Add
`polish_context_enabled`, default true; Polish off means no surrounding-text capture. Mirror Rust
Settings/read/write and `src/types.ts` together, respecting the no-growth rule through a separately reviewed
extraction. Show a clear capture setting and content-free status, including the cloud-context disclosure.

| Platform | Approach and fail-closed rules |
|---|---|
| macOS | AX SelectedTextRange + bounded StringForRange. Reject Secure Input, AXSecureTextField, password managers and unknown apps. Terminal unsupported. Never set AXEnhancedUserInterface or AXManualAccessibility. |
| Windows | `windows` 0.62 is present, Accessibility feature is not. Add `Win32_UI_Accessibility` and required COM support; dedicated COM MTA worker, TextPattern/TextPattern2 caret range. IsPassword true, unavailable or failed means reject. Never Ctrl+C. |

Cloud cap: 1,000 characters before + 1,000 selection, total reference <=12 KiB; local: 256/256, <=4 KiB.
Enforce both Unicode character and encoded-byte limits. Do not overload today's known-term string. Keep system
instructions trusted; send transcript and a separate typed **untrusted reference** in JSON user data.
Dictionary terms stay distinct; context cannot issue instructions or add facts. Update all provider adapters,
including stdin agent transports, and injection evals. New cursor-boundary logic needs bounded preceding
punctuation classification, not one character: abbreviations, quotes, brackets, decimal, URL/code and sentence
starts. No context or uncertain classification means no guessed edit. Recheck the target at delivery; drop
stale context and unsafe boundary changes.

**CLI first:** proposed `voicetypr context capture --dry-run --json` returns metadata only; explicit
`--include-text` writes only to the private CLI output; `--delay-ms` exercises target changes. Add a private
reference-input option to `voicetypr polish` for identical prompt/eval tests without desktop capture.
**Acceptance:** deadlines and Island timing measured; all statuses covered; secure/denied/unknown never emit
text; stale generations rejected; serialization tests prove text cannot enter persistent metadata; default
follows Polish. **NEEDS-SMOKE matrix:** Mac TextEdit, Pages, Mail, Safari/Chrome forms, Electron editors/chat,
Terminal rejection, password managers, Secure Input, AX denial/regrant, Spaces/fullscreen and focus-preserving
Island. Windows Notepad, Word, Outlook, Edge/Chrome forms, Electron, unsupported terminals, password fields,
elevated apps/UIPI and unavailable UIA providers. Both: rich text/contenteditable, selection replacement,
code, multilingual punctuation, rapid takes, focus/range changes, hung apps, sleep/wake, no permission.
**Risks:** AX/UIA stalls, inconsistent ranges, privacy leakage and silent focus drift.

## 5. D. Keep only the selected agent CLI warm

**Why:** lower Polish delay without idle processes for every installed agent. **Estimate:** 5–8 days, after
the beta.5 fold-in and private-input fix (082).

HEAD `ai/agent_cli.rs::AgentCliRuntime` cold-spawns per call; existing pi RPC is used for model discovery, not
a retained dictation session. Proposed focused `ai/agent_cli/{warm_session,pi_rpc,opencode_server}.rs`, no
monolith growth. Own exactly one selected-provider lifecycle, 10-minute idle timeout, serialized requests,
bounded startup/output, crash recovery and cold/raw fallback. Model/provider change, disable, logout or quit
closes the old child tree. Keep content out of disk/session history, logs and inherited user integrations.

| CLI | Design |
|---|---|
| pi / omp | Capability-checked RPC, `new_session` per dictation; disable omp cache warming. Prove reset and isolation on supported versions. |
| Codex | Retain isolated `exec`; app-server is not accepted as production-ready. No fake warm daemon. |
| OpenCode | Private `serve`, loopback, per-launch auth, no shared user server; version-gate API and isolation. |
| Claude | Build on the beta.5 hot spare after its implementation and private-input fix pass review (082); verify isolation before retaining it. |

**CLI first:** proposed `voicetypr agent warm --selected --json` and
`voicetypr agent status --json`, then repeated existing stdin `voicetypr polish
--provider "$SELECTED" --json`. CLI must address the same selected session owner,
not create unrelated warm processes per invocation.
**Acceptance:** cold/warm comparison, fresh session per take, zero cross-take
content, only selected child survives, idle expiry and cancellation verified.
**NEEDS-SMOKE:** macOS shell resolution and quit; Windows executable/shim policy,
process-tree cleanup, sleep/wake; both provider switches, crash and auth failure.
**Risks:** RPC drift, hidden session persistence, warm RAM and shared-owner IPC.

## 6. E. Silero VAD, shadow first

**Why:** distinguish breath/hum/noise from speech and improve long-audio splits. **Estimate:** 4–7 days. Use
our integration of the MIT Silero model, not TEN.

Choose **Rust Silero ONNX via ort**, not mac-only FluidAudio VadManager: one decision path serves Windows
Parakeet and all other engines on both OSes. No ort/parakeet-rs dependency exists in the beta.5 HEAD
manifest/lockfile; the Windows spike introduces ORT transitively through parakeet-rs. Align the ort
version/static-link policy with that branch; macOS VAD adds a new runtime cost and needs explicit size/RSS
measurement. Proposed `audio/{silero_vad,vad_segments}.rs`, outside the real-time callback. Bound worker
queues, preserve source timestamps and whole speech spans.
`audio/speech_evidence.rs::classify_speech_evidence` already has calibrated energy/transient gates; 059 Phase
2 proposes shadow VAD. Preserve existing behaviour while recording content-free shadow decisions on real
speech. Uncertain/missing VAD means pass-through. Promote enforcement only after a reviewed false-negative
study; one beta of shadow evidence is the default. VAD boundaries may supplement A's existing quiet-gap
splitter after comparison, but never drop non-VAD spans or block A's current long-audio fix.

**CLI first:** proposed `voicetypr vad analyze --file "$CLIP" --shadow --json`. **Acceptance:**
quiet/short/multilingual speech preserved, bounded CPU/RSS, state reset per recording, no live gate changes in
shadow mode; chunk coverage and tail preservation verified. Pin model/hash/licence. **NEEDS-SMOKE:** Mac
CPU/Metal contention and Windows low-end CPU, Bluetooth/ resampled input, fans/music/hum, whispers, clipped
first words and long takes. **Risks:** quiet-speech rejection, dependency/binary growth and boundary word
loss.

## 7. F. Clipboard receipt restore

**Why:** avoid restoring before a slow app consumes the paste and avoid overwriting a user's newer clipboard
copy, even if its text is identical. **Estimate:** 4–6 days, including a platform feasibility spike.

Existing designs: `plans/archive/007-clipboard-restore-timing.md` and the 2026-09-30 research note; existing
implementation is in `commands/text.rs`. Proposed `writing/clipboard_transaction/{mod,macos,windows}.rs`:
retain insertion generation, original carry-forward for rapid takes and copy-only outcomes. Add OS
ownership/change tokens, not only transcript equality. A read receipt is not proof the target inserted text.
Neither NSPasteboard changeCount nor Windows clipboard sequence number alone proves a read. Spike a lazy text
provider/render-request receipt (macOS pasteboard provider, Windows delayed rendering) with target attribution
where supported. Preserve clipboard formats safely; never silently replace non-text originals with text. On
unsupported/ambiguous receipts or bounded timeout, leave the transcript for manual paste rather than claiming
success or blindly restoring. Document capabilities; do not promise universal OS receipts. Founder reviews
degraded UX.

**CLI first:** proposed `voicetypr clipboard verify --fixture slow-reader --json` using a controlled native
reader and mock receipts, then real target checks. **Acceptance:** receipt plus ownership plus current
generation required for restore; same-text user copy and superseded take never overwritten; timeout, paste
failure, no permission and keep-in-clipboard remain safe. **NEEDS-SMOKE:** Mac native/Electron/browser and
Windows Notepad/Word/Chromium, slow readers, clipboard managers, rich/image originals and rapid identical
takes. **Risks:** provider callback threading, readers prefetching, no reliable target attribution and loss of
non-text formats. Receipt feasibility is unresolved.

## 8. G. Secure Input hotkey fallback

**Why:** avoid a stuck recording or apparently dead shortcut after password entry. **Estimate:** 3–5 days.

`plans/022-native-trigger-engine.md` §6.8 proposes Secure Input release-all; the research note proposes
fallback, but committed keytrigger has no matching Secure Input handling. Proposed `recording/secure_input.rs`
plus a small `crates/keytrigger` platform adapter. Detect macOS Secure Input, release active holds/reset
matcher, show a content-free explanation and stop capture promptly. Never bypass protected fields or use
context capture there. Spike an alternate public shortcut registration only for supported key chords, mutually
exclusive with the tap; no double firing. Bare modifiers/unsupported bindings use an explicit tray/pointer
start and Island stop/cancel fallback, with normal security checks. Recreate/reconcile the tap when secure
mode ends. Windows has no equivalent macOS Secure Input mode: preserve ordinary hooks, explain
UIPI/elevated-target limits and never inject into the secure desktop.

**CLI first:** proposed `voicetypr hotkey diagnose --json` and `voicetypr hotkey verify --fixture secure-input
--json` with injected state changes. **Acceptance:** no stuck mic, no duplicate start/stop, reliable recovery
and honest unsupported-binding guidance; no captured protected text. **NEEDS-SMOKE:** Mac password
fields/managers, Terminal Secure Keyboard Entry, hold activation, permission revoke/regrant and sleep/wake;
Windows lock/UAC, elevated targets and normal hold-key regression. **Risks:** OS shortcut coverage, false
fallback confidence and transition races.

runs automated gates on remote/CI infrastructure, never as part of this task. Green tests prove contracts
