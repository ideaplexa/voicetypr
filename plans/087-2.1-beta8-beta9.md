## 4. "Only failed" audio saving (beta.8 item 1)

Today: with "Don't save", a failed take is kept in memory for 10 minutes (30 s for no speech),
at most 3, and is lost when the app quits (`recording/kept.rs`, `RecoveryKind::ttl_ms`).

Contract:
- Recording audio setting gets three choices: **Don't save**, **Only failed** (new), and keep for
  N days / forever.
- **Default "Only failed" for everyone**, including current "Don't save" users (founder decision).
  Migration follows invariant 9: Rust settings and `src/types.ts` together; existing
  `save_recordings: false` becomes Only failed once; users who pick "Don't save" afterwards stay
  there. Show the change once in What's new.
- Only failed keeps a failed take on disk until it is retried successfully, discarded, or
  7 days pass; it survives restarts and appears in Home "Needs you". A successful retry deletes
  the audio. Nothing else is kept.
- "Don't save" keeps today's short in-memory window so Retry still works for 10 minutes.
- Keep the existing protected-path and generation guards; no audio, path or transcript in logs.
- Needs adversarial review (data loss, storage, migration) and a real-Mac check: fail, quit,
  relaunch, retry from Home; retry-fails card; Delete audio removes the file.

## 6. Shadow VAD runtime decision and evidence

The Silero branch is rebased onto `feat/parakeet-windows-v3` at `fad6b8a5`,
including `cc686d0a`'s terminal ONNX shutdown admission. The five earlier

### Why the runtime changed

A runtime CPU guard cannot stop AVX2 instructions in a statically linked
pyke ORT `.CRT$XCU` initializer before `main`. Founder-supplied evidence:
[pandacode #205](https://github.com/aicodeking/pandacode/issues/205),
[Concat #313](https://github.com/jub0t/Concat/issues/313), and Concat commit
`d1184840`'s official dynamic-runtime fix, verified there on Ivy Bridge.
Do not mistake a green post-main guard test for an old-CPU launch proof.

VAD uses existing whisper-rs 0.16.0 / whisper-rs-sys 0.15.0 CPU
`WhisperVadContext`, `use_gpu=false`, one thread, ggml Silero v6.2.
The vendored `whisper.cpp/src/whisper.cpp` reads the model's version/window
and tensor layout, exposes per-window probabilities and resets LSTM state
inside `whisper_vad_detect_speech`. No v5 fallback is selected.
The model is 885,098 bytes, MIT, SHA256
`2aa269b785eeb53a82983a20501ddf7c1d9c48e33ab63a41391ac6c9f7fb6987`.
Source/provenance: `src-tauri/models/silero/README.md` and `provenance.json`.

The shadow contract is unchanged: after-attempt timing, one bounded worker,
no queue, no callback inference, no drop/trim/gating/chunk changes, original
leading silence and tail, no normalization, fresh recurrent state, numeric
telemetry and the same consent guard. Probability threshold is still 0.5
without segment-duration filtering. Incomplete results mean unknown.
The 250 ms budget is cooperative, not a native preemption guarantee:
whisper.cpp's VAD API has no abort callback and processes a bounded whole take
in one call. Checks before/after that call discard over-budget results,
including cleanup time. The slot stays occupied until destruction finishes;
quit attempts a bounded drain before analytics teardown. Long/slow takes need hardware timing.

**Quit follow-up:** the original drain was unbounded; this is corrected.
Admission closes at exit entry. The ordered VAD drain waits at most **250 ms**
(one absolute deadline, not extended by wakeups). If native work is still active,
remote-server/media/analytics cleanup proceeds in the existing order, followed
by terminal process exit without C++ static destruction (`_exit` on Unix,
`TerminateProcess` on Windows), never unsafe native-thread cancellation.
When work was admitted at exit entry, a separate **8 s absolute exit watchdog**
is armed before cache teardown, matching the recorder's existing 8 s budget.
It is canceled only after VAD fully drains; otherwise it also bounds an earlier
or later teardown stage stalled through shared native state. No active VAD means
no watchdog. Late native results/reports are discarded and no new work enters.
Thread-spawn failure or unwinding with an armed guard takes the same safe
terminal exit. Scheduler/OS termination overhead is not a hard-real-time claim.
Tests hold an unfinished lease through the drain deadline and use isolated child
processes to verify watchdog termination, cancellation and bypass of C exit
handlers. GUI quit remains NEEDS-SMOKE.

Native log callbacks are installed once during CLI/app bootstrap, after CPU
admission and before any native workers. They never dereference or emit native
text. A caller-thread ERROR marks the VAD result unavailable: this is necessary
because the pinned whisper.cpp frame loop logs a compute failure but can still
return success with a zero-filled probability tail. Tests cover this adapter
contract; they do not fault-inject the native backend. Whisper's native text
diagnostics are suppressed too; transcription algorithms are unchanged.

### Windows Parakeet and CPU baseline

Only Windows x64 depends on `ort =2.0.0-rc.13`, `load-dynamic`, API 28.
Parakeet-rs 0.3.8 defaults remain disabled. No pyke binaries, static ORT,
DirectML or ORT on either Mac architecture. Windows keeps beta.8's conservative
Parakeet CPU admission, independent of VAD's AVX/AVX2/FMA/F16C gate.

The official Microsoft CPU package is
`https://github.com/microsoft/onnxruntime/releases/download/v1.28.0/onnxruntime-win-x64-1.28.0.zip`.
ZIP SHA256: `abef733dacbe2f571547a7150b479b5cb9cc0df22f96c24983a42cadb1b4f8bc`.
`lib/onnxruntime.dll`: 15,809,848 bytes, SHA256
`18370c375f07357fa5874344a9d9ac17e6b6fe1eb18b1dd209d79483b4470257`.
The ZIP's exact LICENSE and ThirdPartyNotices.txt are pinned and packaged.
The unmodified DLL retains Microsoft's Authenticode signature and hash.
Do not re-sign this Microsoft DLL. Existing updater/Store package signing
flows stay unchanged; no separate bundled-PE signing pass is configured here.
Signing an application executable alone does not cover its sibling DLL.

The only load path is absolute `current_exe().parent()/onnxruntime.dll`,
checked against its size/hash before `ort::init_from`. No PATH, System32,
settings or current-directory fallback. Explicit Parakeet use or startup with a
saved selected Parakeet engine/model may load it, only after CPU admission.
Unselected engines, unavailable model files and unsupported CPUs do not preload.
The selected-model recheck and terminal shutdown admission remain in force.
Missing/corrupt/wrong-version bytes give a clear unavailable error and do not
terminate the app. Terminal shutdown remains closed, reusable unload unchanged.
The runtime size/hash comes from the embedded provenance, not installed mutable
metadata. ORT environment creation explicitly disables Microsoft's native
telemetry, independent of the application's existing analytics-consent guard.
It also supplies a discard-only native logger: the default ORT stderr logger
can include paths on session errors, even when Rust's error is sanitized.
NSIS installs the staged DLL beside the executable; MSIX stages at package root
and verifies the final unpacked package. Missing or changed notices fail closed.
The import check rejects ORT/DirectML native imports and a native
`OrtGetApiBase` definition in the matching main-exe linker MAP. A symbol-string
search alone would falsely reject the dynamic loader and is not used.

Windows workflows plus Intel release and `ci.yml` pin `GGML_NATIVE=OFF`,
`GGML_AVX/AVX2/FMA/F16C=ON`, all four actual AVX512 options off.
BMI2 and AVX-VNNI are explicitly off so ggml does not add another ISA requirement
outside the VAD gate. These flags also pin **in-process Whisper CPU code**;
the Whisper transcription path is otherwise unchanged. On MSVC, FMA/F16C
are implied by `/arch:AVX2`; on Clang they are explicit CMake options.
Rust cache keys include GGML because this whisper-rs-sys build does not emit
Cargo rerun triggers for those environment variables.
The six policy calls use `.github/actions/ggml-cpu-baseline/action.yml` after
checkout and before Rust caching, rather than maintaining six copies.

### Retained upstream native limitations

The independent native review found two limitations in the selected existing
whisper-rs 0.16 / whisper-rs-sys 0.15 backend, not fixed by Rust catch_unwind:

- Severe native weight-buffer allocation failure can abort. In whisper.cpp's
  VAD loader, `ggml_backend_alloc_ctx_tensors_from_buft` is unchecked before
  subsequent tensor-buffer use. A C++ assertion/abort is not a Rust panic.
  Graceful native-OOM handling would require a maintained upstream/native patch
  or process isolation. Neither is silently introduced in this migration.
- `WhisperVadContext::new` converts the filename CString with `into_raw` and
  does not reclaim it. Fresh per-take contexts therefore retain a small filename
  allocation per analysis in the upstream wrapper. Model buffers/contexts and
  private temporary files are still released. RSS measurements are short runs,
  not proof of leak-free lifetime memory.

These are explicit follow-ups/acceptance decisions, not resolved review findings
or hardware passes. Vendoring the native crate or adding a helper process needs
a separate scope decision; this change keeps the requested existing wrapper.
